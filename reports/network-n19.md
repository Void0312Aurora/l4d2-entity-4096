# N19：修正 N4-F 迁移方向与位移编码宽度；表降级为候选清单

> review 指出的 P0 成立：N18 的 `disp_new = disp + 0x100` 把栈变量往**高地址**移了。
> 正确关系是 `disp_new = disp_old - 0x100`（EBP 位移为负，往低地址搬）。另修正 `-0x-8B` 这类格式化错误。

## 1 为什么 disp8 站点全部需要加宽

被迁移区间的旧位移范围是 `[-0x180, -0x80]`（disp8）与 `[-0x180, -0x8]`（disp32）。
对 disp8 站点：`new = old - 0x100`，即使 `old = -0x80`，`new = -0x180`，已超出 disp8 的 `-128..127`。
因此**每一个 disp8 站点都必须把 ModR/M 从 `mod=01` 改成 `mod=10` 并补 3 字节**。
这不再是 N4-S 那种「定长操作数原地替换」，而会改变指令长度，进而影响其后的指令地址与相对跳转。

## 2 表的可用性边界

- 本表由**启发式字节枚举**（按 ModR/M `rm=101`）产生，已知会产生误报：
  例如函数入口 `0x10119F50` 的 `55 8B EC` 被当成 `mod=01,rm=101` + disp8 `0x8B`（= `-0x75`）；
- 必须用反汇编器给出真实指令边界后逐项对账：删误报、补漏报、核实每条指令的有效地址；
- 在完成对账前，本表**不具备补丁生成资格**，只作为审计输入。

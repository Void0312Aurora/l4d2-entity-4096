# N17：帧位图生产者的两种直接写法都未命中；N4-B/N4-F 迁移清单与栈布局候选

> 本轮按 review 调整优先级：先找 `CFrame+0x0C` 的写入者，再枚举发送端栈布局。
> 生产者搜索得到**否定结果**：`OR/BTS [reg+idx*4+0x0C]` 的 disp8 与 disp32 两种编码全镜像 0 命中。
> 这不等于「没有写入者」，而是说明写入者换了一种形态（预计算指针 / 批量拷贝），这正是下一轮该查的方向。

## 0 本轮结果

| 项 | 结果 |
|---|---|
| `OR [reg+idx*4+0x0C]` disp8 形态 | **0 命中** |
| `OR/BTS [reg+idx*4+0x0C]` disp32 形态 | **0 命中** |
| 结论 | 生产者不是「一条就地 OR」，更可能是「先 `LEA` 出位图基址、再按指针写」或 `memcpy`/批量 dword 写 |
| N4-F 栈布局候选 | 已记录（对象基址 `-0x158 → -0x258`，快照指针保持 `-0x1C/-0x18` 不动） |
| N4-B 迁移清单 | 已列出全部已知牵连点，仍未升级为可应用补丁 |

## 1 生产者搜索：两次否定与解释

搜索一（disp8 形态）：

```
09 <modrm mod=01,rm=100> <SIB scale=10> 0C     ; OR [base + index*4 + 0x0C], reg
```

搜索二（disp32 形态，含 `BTS`）：

```
09/0B <modrm mod=10,rm=100> <SIB scale=10> 0C 00 00 00
0F AB <modrm mod=10,rm=100> <SIB scale=10> 0C 00 00 00
```

两次均 0 命中。结合 N16 已确认「读取侧是 `[CFrame+0x0C]`」，可以排除「写入方与读取方用同一种
就地寻址」的假设。合理的候选形态：

| 形态 | 特征 | 检索方式 |
|---|---|---|
| 预计算基址 | `LEA EAX,[frame+0xC]` 提前进寄存器，之后 `OR [eax+idx*4]` | 找 `LEA reg,[reg+0xC]` 的消费者 |
| 批量拷贝 | `memcpy(dst=frame+0xC, src=?, 0x100)` | 找 dest 为 `frame+0xC` 的 `memcpy` |
| 逐 dword 写 | `MOV [frame+0xC+k*4], value` | 找 disp 序列 `0C/10/14/...` 的连续写 |

下一轮优先查前两类：`LEA <reg>,[<frame>+0xC]` 的消费者集合，以及 `memcpy` 的 dst 计算。

## 2 N4-F：发送端栈布局候选（对象下移、快照指针不动）

发送端 `FUN_10119F50` 栈帧 `0x180`，对象基址 `EBP-0x158`，`sizeof ≈ 0x144`。
推荐「**尾部对齐**」方案，让两个快照指针留在原栈槽：

| 成员 | 原（相对 EBP） | 新（相对 EBP） |
|---|---|---|
| 对象基址 | `-0x158` | **`-0x258`** |
| 头部（0x3C B） | `-0x158 … -0x11D` | `-0x258 … -0x21D` |
| 位图（256/512 B） | `-0x11C … -0x01D` | `-0x21C … -0x01D` |
| 新快照指针 `+0x13C` | `-0x01C` | **`-0x01C`（不变）** |
| 旧快照指针 `+0x140` | `-0x018` | **`-0x018`（不变）** |
| 栈帧 | `0x180` | `0x280` |

校验：`-0x258 + 0x23C = -0x1C`、`-0x258 + 0x240 = -0x18`。

优点：发送端对两个快照指针的既有访问（`0x1011A032` 的写、`0x1011A043` 的空分支写）**无需改位移**；
缺点：对象头部与位图的所有 EBP 相对访问要整体下移 `0x100`，且 `LEA EAX,[EBP-0x158]` 必须改为 `-0x258`。

必须枚举的对象（按 N4-S 的教训，一处不能漏）：

1. `FUN_10119F50` 中所有 `[EBP-0x158 … EBP-0x15)` 区间的访问（对象头部 0x3C 字节）；
2. 所有 `[EBP-0x11C … EBP-0x1D]` 的访问（位图 0x100 字节）；
3. 对象**下方**的局部（`EBP-0x160` 的 `arg1` 保存位、`EBP-0x164` 的 `param2`），它们不受影响但要确认；
4. `FUN_101196C0` 内经 `EDI` 的 `+0x13C/+0x140` 访问（改为 `+0x23C/+0x240`）；
5. `LEA EAX,[EBP-0x158]`（改为 `-0x258`）及任何把它当参数传递的调用。

- 两处池初始化 `FUN_1028a300(0x11c, 0x80, 2, 0, 0)`（`FUN_10093970`、`FUN_10118E00`）；
- 接收端分配 `FUN_101ae9b0(0x11c)`（`FUN_101846C0`）；
- 构造器 `FUN_10093E20` 的 `memset` 与四个字段写；
- 析构/链表操作 `FUN_1011DB40`、`FUN_10093C80`（`+0x114`）；
- 发送端读 `[frame+0x118]`（`0x10119FCB`、`0x1011A025`）与接收端 `[frame+0x118]`（`0x101846C0` 附近）。

**仍未升级为补丁**：位图生产者为 0 命中、成员访问尚未完整枚举；现在动手会重演 N4-S 的漏项问题。

## 1 实例：`sv` 作为 `this` 的编译形态

```
0x10003080  83 3d 5c 55 64 10 02   CMP dword [0x1064555C],2     ; sv+4
0x10003087  7d 03                  JGE 0x1000308C
0x10003089  33 c0                  XOR EAX,EAX
0x1000308b  c3                     RET
0x1000308c  b9 58 55 64 10         MOV ECX,0x10645558           ; sv 基址
0x10003091  e8 1a 5e 12 00         CALL 0x10128EB0              ; this-call
0x10003096  85 c0                  TEST EAX,EAX
0x10003098  74 ef                  JZ 0x10003089
0x1000309a  8b 10                  MOV EDX,[EAX]
0x1000309c  8b c8                  MOV ECX,EAX
0x1000309e  8b 42 0c               MOV EAX,[EDX+0xC]
0x100030a1  ff e0                  JMP EAX                       ; 尾调用
```

三点价值：

1. `0x10645558` 被显式装入 `ECX` 后立即 `CALL`——确认它是被当作 `this` 使用的对象基址；
2. 调用前读 `[0x1064555C]`，即 `sv+4`，与 N2 记录的 `0x1064555C` 引用互相印证；
3. 这是**成员函数 this-call** 的标准形态，与 `SV_SpawnServer` 的调用方式同构。

## 2 调用点验收判据（形式化，供生成器使用）

对每个候选调用点 `p`（`E8 rel32`）：

```python
target = (p + 5 + sign_extend32(rel32)) & 0xFFFFFFFF
assert target == 0x10123B20
```

再对 `p` 之前的数据流做**到达定义**检查，只接受以下形态：

```
B9 58 55 64 10        MOV ECX,0x10645558
...（无 CALL、无对 ECX 的写、无可能改 ECX 的路径）
E8 rel32              CALL 0x10123B20
```

拒绝条件：

- `MOV ECX,…` 与 `CALL` 之间存在任何 `CALL`（被调方可能改 `ECX`）；
- 中间存在 `POP ECX`、`XOR ECX`、`MOV ECX,reg` 等重定义；
- `ECX` 来自参数/内存而非该常量（此类调用点不能证明别名，需要单独归类）。

同时按 review 的要求记录两条边界：

- **一个正确调用点不等于全部路径**：要么枚举全部有效调用点，要么证明其他入口最终汇入同一路径；
- **未找到 `E8` 不等于不可达**：还需排除函数指针表、虚调用、跳转桩与反汇编漏识别的交叉引用。

## 3 N4-E：`0x10429308` 的影响面

同一条 `MOV EAX,0x800` 供给两处 store：

```
0x10123DA2  MOV EAX,0x800
0x10123DA7  MOV [ESI+0x218],EAX     ; sv.max_edicts（若 this=sv）
0x10123DAD  MOV [0x10429308],EAX    ; 另一个容量变量
```

因此 `capacity_imm` 改动会**同时**把 `[0x10429308]` 改为 4096。这不是缺陷，但必须确认它不关联
任何未扩容的 2048 项固定数组。分类方法（按读取点数据流）：

| 类别 | 判据 | 风险 |
|---|---|---|
| 对外公布的最大实体数 | 是否流入网络字段/字符串/日志 | 低（同步扩容正确） |
| 实体/快照管理容量 | 是否与 `alloc` 尺寸、循环上界同源 | 中（须与 `sv.max_edicts` 一致） |
| 固定数组的边界判断 | 是否存在 `0x800` 硬编码数组/位图 | **高**（会越界或截断） |

下一轮对 `0x10429308` 取 `xrefs`，逐点归类；若发现它与 `FUN_1004E310` 的 `0x800` 位图或
`FUN_1011D900` 的 `short[2048]` 同源，则这两项必须与 N4-E 同步迁移。
